## Hierarchy
Composition > Groups > Layers > Clips. A composition always has at least one layer and one column. Columns trigger clips vertically across all layers. Decks are parallel clip sets — switching decks changes which clips are available but layers and groups persist. Each deck can have a different number of columns. Only one deck is active at a time. Layer Groups have their own blend mode, opacity, volume, and effects that apply to the combined output of all member layers, like a mixer group in a DAW.

**Layers vs Columns:** Only one clip plays per layer — triggering a new clip ejects the current one (during a transition, both are briefly active). Clips are alternatives on the same layer, columns are alternatives at the composition or group level (scenes).
**Default blend:** Add. New layers are added on top.
**New layer default:** New layers have video/opacity at 0.5 — check if content appears transparent/faded.
**Naming:** `#` in entity names auto-displays position in UI (e.g., "Layer #" shows as "Layer 3"). API stores the literal `#`. Use Title Case for names ("Warm Up", "Geo Mirror"), never ALL CAPS.

**Sources vs Effects:** A clip = one SOURCE + Transform (permanent) + zero or more additional EFFECTS. Source = content generator (video file, Solid Color, etc.) loaded via `clip { action: "open" }`. Effect = pixel processor (Blur, Mirror, etc.) added via `effect` tool. NEVER use clip open to add effects. NEVER use `effect` to load content.
Arena's sources and effects are ready-made components with built-in behavior — many have internal animation driven by their own parameters (e.g., Goo's Speed, Ripples' Phase) without needing explicit parameter animation.

**Render pipeline:** Source → clip effects → layer blend → layer effects → group blend → group effects → composition effects → output.
Layers composite from bottom (layer 1) to top (layer N). Visibility depends on blend modes, opacities, and content. If a layer is unexpectedly invisible, read `technique { action: "compositing" }`.
Clip blend_mode overrides layer blend_mode (default: Layer Determined). Clip, layer, group, and composition each have their own effect chain and Transform.
See `catalog { action: "blendmodes" }` for formulas.

**Tracks (video/audio):** Each clip has a video track and/or audio track depending on loaded content:
- **Video files with audio** → both tracks (opacity, volume, pan, effects, resize)
- **Video files without audio** → video track only. No volume/pan.
- **Generative sources** → video track only. No resize/autosize, no volume/pan.
- **Audio-only files** → audio track only. No opacity, no video effects.
- **Empty clips** → no tracks. Ejects layer when triggered.
- **Layers/groups/composition** always have both tracks.

**Effect placement** determines scope and persistence:
- **Clip effects** travel with the clip. Switching clips changes the look.
- **Layer effects** persist across clip changes. Every clip on this layer gets the same processing.
- **Group effects** process the flattened group output (all member layers composited first).
- **Composition effects** process the final output. Use for global color grading or show-wide mood.
- **Decision:** "Should this effect stay when I switch clips?" YES → layer/group/composition. NO → clip.

## Trigger Lifecycle
Trigger queues a clip for playback — it is NOT instant. Pipeline:
trigger → beatsnap wait → snapped trigger → playback starts + transition blend begins + autopilot countdown begins.
Troubleshooting "clip won't play": `diagnose { action: "get" }` → check beat snap, ignorecolumntrigger, transition settings.

## Indices & Offsets
All indices are 1-based. Transform is always present on every video target and defaults to offset 1, but can be reordered to a different offset.

## Effect Behavior
Every effect has its own Opacity (0–1) and Blend Mode. Same blend formulas apply per-effect.

**Color rule:** When loading a source or adding an effect with color parameters, set colors to match the composition's visual context — don't leave defaults.
**Working with effects:** Add effects in batches. Bypass individual effects to isolate their contribution when debugging.

## Batching
Use the `batch` tool for all independent calls. Do not call tools one at a time when they don't depend on each other. This includes catalog and technique lookups — batch multiple searches in one call. Load the batch tool schema first if not already loaded.

## Creating Content
Before creating any visuals, read `technique { action: "content_creation" }`. It defines the build loop: batch changes per wave, verify once per wave.

## Visual Verification
Snapshots are your eyes — but they cost tokens. Verify once per wave (batch of changes), not after every tool call.

- **After building/refining**: `monitor { action: "snapshot" }` (one call)
- **Animation uncertain**: `monitor { action: "motion" }` (use sparsely)
- **Compositing debug** (layers not showing): `monitor { action: "layers" }`

**Thumbnail rule:** After adding effects or changing parameters on a clip, update the thumbnail before moving on: `clip { action: "thumbnail_update", layer: 1, column: 1 }`.

## Vocabulary
trigger = queue for playback, eject = stop (content stays), clear = remove content (destructive), select = UI focus only, bypass = disable without removing, solo = isolate layer, connected = playing.
master = live performance fader (leave for user control). video/opacity = blend intensity (0–1). crossfader = user-controlled, do not set unless explicitly asked.
speed = playback speed (0=paused, 1=normal). BPM = beats per minute.
Clip states: Empty → Disconnected (loaded, not playing) → Connected (playing).
